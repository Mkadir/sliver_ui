# Wire loaders beyond Obfuscate alone

**Sliver UI must treat antivirus-aware delivery as a layered pipeline—network camouflage, host/payload form factor, and runtime behavior—because Obfuscate and Evasion checkboxes do not defeat 2024–2026 AV/EDR.** Stock implants are killed primarily by **protobuf and BishopFox path YARA**, then by **injection and unbacked executable memory** behaviors, while BishopFox itself places AV bypass **outside Sliver’s scope** and points operators at packers, crypters, and stagers ([Sliver Docs: Anti-virus Evasion](https://sliver.sh/docs?name=Anti-virus+Evasion); [Elastic Multi_Trojan_Sliver](https://github.com/elastic/protections-artifacts/blob/main/yara/rules/Multi_Trojan_Sliver.yar); [Immersive Labs](https://www.immersivelabs.com/resources/c7-blog/detecting-and-decrypting-sliver-c2-a-threat-hunters-guide)). Operators who keep working against updated Defender and Elastic stop dropping raw EXE/service PEs and instead generate **shared/shellcode**, convert via **Donut or sRDI**, optionally encode, then wrap in a **custom or sideload loader**—with Linux shifting to **`.so` + memfd/`LD_PRELOAD`** rather than Windows RDI ([Fortbridge](https://fortbridge.co.uk/research/reforging-sliver-how-simple-code-edits-can-outmaneuver-edr/); [NetSPI sRDI](https://www.netspi.com/blog/technical-blog/adversary-simulation/srdi-shellcode-reflective-dll-injection/); [BallisKit](https://blog.balliskit.com/tutorial-sliver-c2-with-balliskit-macropack-and-shellcodepack-452e94c24b19)). This fork already owns the **network OPSEC** half (`/http-c2`, traffic encoders, listener camouflage) and has an unused **RDI API**; the product gap is a first-class **Loaders** surface that wires `ShellcodeEncoder`/`SGNEnabled`, deep-links implants into a transform pipeline, and ships honest checklists—without claiming **FUD** or shipping a commercial crypter. Success for the UI is fewer operator mistakes (wrong format, raw PE on disk, default HTTP profile), not a VirusTotal score.

## Static signatures burn stock implants; behavior burns the rest

On disk, unmodified Sliver is a **known-bad family**. Public YARA from Immersive Labs, Elastic, Wazuh, and community playbooks keys on **`sliverpb`**, **`github.com/bishopfox/`**, protobuf method names such as `ScreenshotReq` / `HTTPSessionInit`, Go `buildid`/`Go buildinf`, and DLL export strings like `GetJitter` and `VoidFunc` ([Immersive Labs SliverC2-Forensics](https://github.com/Immersive-Labs-Sec/SliverC2-Forensics/blob/main/Rules/sliver.yar); [Elastic Multi_Trojan_Sliver](https://github.com/elastic/protections-artifacts/blob/main/yara/rules/Multi_Trojan_Sliver.yar); [Fortbridge](https://fortbridge.co.uk/research/reforging-sliver-how-simple-code-edits-can-outmaneuver-edr/); [Wazuh](https://wazuh.com/blog/detecting-sliver-c2-framework-with-wazuh/)). Typical Windows implants are **multi-megabyte Go binaries** (~16–30 MB in published writeups), which raises visibility and frustrates module stomping ([Immersive Labs](https://www.immersivelabs.com/resources/c7-blog/detecting-and-decrypting-sliver-c2-a-threat-hunters-guide); [Fortbridge](https://fortbridge.co.uk/research/reforging-sliver-how-simple-code-edits-can-outmaneuver-edr/)). **Garble/`--obfuscate` fails to rename protobuf schema strings**, a limitation BishopFox maintainers acknowledge, so symbol renaming leaves the strongest family signatures intact ([BishopFox/sliver#1760](https://github.com/BishopFox/sliver/issues/1760); [The DFIR Report](https://thedfirreport.com/2024/08/12/threat-actors-toolkit-leveraging-sliver-poshc2-batch-scripts/)). Light packing that only raises section entropy often **increases** heuristic suspicion while those strings remain.

At runtime, Microsoft Defender for Endpoint and Elastic-class agents hunt **technique**, not brand. Sliver’s default migrate/sideload/spawn-dll/execute-assembly path follows **`VirtualAllocEx` → `WriteProcessMemory` → `VirtualProtectEx` → `CreateRemoteThread`**; MDE alerts on injected code, GetSystem into `spoolsv.exe`, sacrificial **`notepad.exe`**, and PsExec-style services named “Sliver” / “Sliver implant” under `%WINDIR%\Temp` ([Microsoft Security Blog](https://www.microsoft.com/en-us/security/blog/2022/08/24/looking-for-the-sliver-lining-hunting-for-emerging-command-and-control-frameworks/)). Fortbridge’s 2025 Elastic lab showed that after static scrubbing, **network DLLs loaded from unbacked memory** still alerted, and many built-in post-ex commands continued to fire behavioral rules ([Fortbridge](https://fortbridge.co.uk/research/reforging-sliver-how-simple-code-edits-can-outmaneuver-edr/)). Elastic 8.11+ kernel ETW call-stack rules target shellcode, unbacked callers of sensitive APIs, direct/indirect syscalls, and AMSI/ETW patching—so **byte encoders alone do not equal evasion** ([Elastic ETW call stacks](https://www.elastic.co/security-labs/doubling-down-etw-callstacks)). Default Donut AMSI bypass inside Sliver shellcode generation is itself signatured; operators who care disable or replace it ([Fortbridge](https://fortbridge.co.uk/research/reforging-sliver-how-simple-code-edits-can-outmaneuver-edr/)). Network defaults (`.woff` stager, `.js` poll, `.html` key exchange, custom Base32/58 alphabets, nonce `_` params) are fingerprintable via Immersive Snort/Sigma and Corelight packages ([Immersive Labs](https://www.immersivelabs.com/resources/c7-blog/detecting-and-decrypting-sliver-c2-a-threat-hunters-guide); [Corelight](https://corelight.com/blog/new-sliver-c2-detection-released-redteam-detected)).

The practical ordering for **authorized** emulation planning, synthesizing Microsoft, Fortbridge, BallisKit, and ScareCrow-class tradecraft: customized **sideload/DLL or mature shellcode loader** ≥ staged shellcode inject ≫ stock shellcode with default Donut AMSI ≫ stock on-disk EXE ≫ stock service with default metadata. Pure “never touch disk” is attractive but **hard for multi-MB Go implants** against EDRs that alert on unbacked RX plus network module loads; public red-team success stories often land on a **thin trusted host process + cleaned shared library** compromise ([Fortbridge](https://fortbridge.co.uk/research/reforging-sliver-how-simple-code-edits-can-outmaneuver-edr/); [BallisKit](https://blog.balliskit.com/tutorial-sliver-c2-with-balliskit-macropack-and-shellcodepack-452e94c24b19)). **No UI option can guarantee undetected delivery**; detections churn monthly and engagement results are environment-specific.

## Split network OPSEC from host payload and runtime hygiene

Mature C2 UIs already separate **malleable traffic** from **artifact packaging**. Cobalt Strike binds a Malleable profile at teamserver start and loads Artifact/Resource kits separately; Mythic splits C2 Profiles from payload-type wrappers; Havoc Yaotl profiles configure listeners while Demon generation exposes sleep/syscall knobs and docs tell operators to use **external** loaders ([HelpSystems kits/profiles](https://hstechdocs.helpsystems.com/manuals/cobaltstrike/current/userguide/content/topics/blog_kits-profiles-scripts.htm); [Mythic C2 Profiles](https://docs.mythic-c2.net/version-2.3/c2-profiles); [Havoc Agent](https://havocframework.com/docs/agent)). Sliver UI should keep that split: **`/http-c2` for network OPSEC**, **Implants + Loaders for host/payload OPSEC**, and **session Advanced tools + checklists for runtime behavior**.

**Network OPSEC** is profile and infra hygiene before generate. Customize named HTTP C2 profiles (paths, extensions, headers, cookies, UA) so implants do not embed documented defaults; prefer HTTPS on 443 with real domains, Let’s Encrypt or valid certs, and website decoys over long-lived mTLS on 8888; optionally attach Wasm traffic encoders ([Sliver HTTPS C2](https://sliver.sh/docs/?name=HTTPS+C2); [Radiant Sec](https://radiantsec.io/docs/tools/sliver/); [Traffic Encoders](https://sliver.sh/docs?name=Traffic+Encoders)). Procedural C2 randomizes URLs per request and embeds a **random subset** of the server profile per implant, which reduces cloneability but does not replace customization ([Sliver HTTPS C2](https://sliver.sh/docs/?name=HTTPS+C2)). The `wininet` driver helps corporate proxy auth and increases hook surface relative to Go’s stack ([C2 Advanced Options](https://sliver.sh/docs/?name=C2+Advanced+Options)). This layer is largely **already implemented** in this fork.

**Host and payload OPSEC** is form factor and packaging. Official guidance rates **beacons with sleep/jitter** above interactive sessions for long-haul presence; prefer **`shared` / `shellcode`** over raw `exe` when AV is present; use execution limits (`--limit-hostname`, domain-joined, datetime, file-exists, locale, username) as sandbox/canary guardrails; treat **SGN as shellcode-format-only** polymorphic encoding, not a general PE packer ([Sliver Payload Compatibility](https://sliver.sh/docs?name=Payload+Compatibility); [generate.go / SGN](https://raw.githubusercontent.com/BishopFox/sliver/master/client/command/generate/generate.go); [tishina](https://tishina.in/opsec/sliver-opsec-notes)). When an EXE is burned, the common Windows recovery chain is: generate **shared DLL or PE** → **Donut or sRDI → PIC** → optional **SGN/XOR** → encrypt into a **custom or sideload loader** → optional HTTP stage-0 → in-memory execute with **beacon first**, interactive later ([NetSPI sRDI](https://www.netspi.com/blog/technical-blog/adversary-simulation/srdi-shellcode-reflective-dll-injection/); [Donut](https://github.com/TheWover/donut); [BallisKit](https://blog.balliskit.com/tutorial-sliver-c2-with-balliskit-macropack-and-shellcodepack-452e94c24b19); [TrustedSec Execution Guardrails](https://trustedsec.com/blog/execution-guardrails-no-one-likes-unintentional-exposure)). Sideloading inherits signed-host reputation but shifts detection to **unsigned/recently dropped DLL loads** beside trusted binaries ([Elastic library hunting](https://www.elastic.co/security-labs/Hunting-for-Suspicious-Windows-Libraries-for-Execution-and-Evasion)).

**Runtime behavior OPSEC** is what happens after callback. Avoid interactive `shell` (Sliver itself warns it is bad OPSEC), default notepad for `execute-assembly`, default PsExec naming, and textbook remote CRT injection on mature EDR; prefer BOFs, in-process execute-assembly, and changed sacrificial processes ([tishina](https://tishina.in/opsec/sliver-opsec-notes); [Radiant Sec](https://radiantsec.io/docs/tools/sliver/); [Microsoft](https://www.microsoft.com/en-us/security/blog/2022/08/24/looking-for-the-sliver-lining-hunting-for-emerging-command-and-control-frameworks/)). BishopFox discussion notes that **sleep obfuscation and direct syscalls are often most effective in the loader**, not inside the Go implant ([Sliver Discussion #1171](https://github.com/BishopFox/sliver/discussions/1171)). UI checklists should gate first drop: customized HTTP profile, unique build per target, lab detonation against target-like EDR, environmental keying/kill switch, encrypt-at-rest stage-0, and rollback plan to disable stage URLs ([TrustedSec](https://trustedsec.com/blog/execution-guardrails-no-one-likes-unintentional-exposure); [tishina](https://tishina.in/opsec/sliver-opsec-notes)).

## Windows and Linux chains diverge after generate

**Windows** owns most of Sliver’s evasion surface: Donut-tuned shellcode, service format, userland unhooking via `--evasion`, CLR/BOF, named-pipe pivots, and sacrificial-process injection ([Sliver Stagers](https://sliver.sh/docs/?name=Stagers); [Payload Compatibility](https://sliver.sh/docs?name=Payload+Compatibility)). Sliver already embeds Donut for `format shellcode` and sRDI helpers for `ShellcodeRDI` / `spawndll`; stock remote inject still uses the classic CRT sequence that advanced EDRs expect ([pkg.go.dev generate](https://pkg.go.dev/github.com/bishopfox/sliver@v1.7.6/server/generate); [tishina](https://tishina.in/opsec/sliver-opsec-notes)). Operators often **disable** native SGN/symbols when an external packer will re-protect, to shrink size and avoid double-noise ([BallisKit](https://blog.balliskit.com/tutorial-sliver-c2-with-balliskit-macropack-and-shellcodepack-452e94c24b19)). ScareCrow-class and commercial OST tooling emphasize **sideload** loaders (AES-encrypted shellcode, unhook options) over dropping unknown EXEs; campaigns pairing ScareCrow with Sliver still expose injection, sleep-mask, and signing-chain telemetry to hunters ([optiv/ScareCrow](https://github.com/optiv/ScareCrow); [Hunter’s Ledger](https://the-hunters-ledger.com/reports/sliver-open-directory/)). For the UI wizard: show **service** with ServiceName/Description hygiene; recommend **shared/shellcode** into Loaders; enable **RDI**, SGN/XOR, and links to `execute-shellcode` / sideload / spawndll / service install; keep Obfuscate/Evasion toggles but with Windows-oriented behavioral disclaimers.

**Linux** is a different product surface. Service format is Windows-only; shellcode is unsupported on `linux/386` and mainly offers **compression** rather than full Donut knobs on amd64/arm64; `--evasion` notes are Windows-centric ([Payload Compatibility](https://sliver.sh/docs?name=Payload+Compatibility); [Stagers](https://sliver.sh/docs/?name=Stagers); [tishina](https://tishina.in/opsec/sliver-opsec-notes)). Delivery tradecraft centers on **shared `.so`**, **`memfd_create` + `fexecve`/`execveat`** (fileless but forensically visible as `/memfd:…`), and **`LD_PRELOAD`** into a chosen process; Sliver’s Linux sideload path writes to memfd and preloads rather than CRT-injecting ([Sliver Third Party Tools](https://sliver.sh/docs/?name=Third%20Party%20Tools); [Purpleshift memfd](https://purpleshift.io/purple/2026-06-29-onsd/); [THC noexec bypass](https://iq.thc.org/bypassing-noexec-and-executing-arbitrary-binaries)). Remote ptrace injection is often blocked by Yama; noisy `execute -o` can leave **defunct children** ([tishina](https://tishina.in/opsec/sliver-opsec-notes)). UI must **filter** formats and loader transforms by OS: hide service and Windows-only RDI/rundll32 tips; emphasize shared/shellcode downloads plus memfd/`sideload -p` checklists; show only encoder/arch pairs from `ShellcodeEncoderMap`; never copy AMSI/ETW language onto Linux forms. Network blending (HTTP profiles, avoid DNS-as-evasion) is shared across platforms ([tishina](https://tishina.in/opsec/sliver-opsec-notes)).

Embed in Sliver UI only what gRPC already exposes: generate formats, **ShellcodeRDI**, **ShellcodeEncoder** / map, **SGNEnabled**, HTTP profiles, stage listeners, and session sideload/spawn-dll/exec-shellcode. Keep custom Nim/Rust/Go/.NET loaders, sideload host pairing, environmental keying, memfd stub compile, phishing macros, sleep masks, and call-stack spoofing as **external tools plus in-UI checklists**—the same honesty Cobalt Strike documents when Artifact Kits get signed and Havoc states Demon was **not designed to be evasive** ([HelpSystems Artifact Kit](https://hstechdocs.helpsystems.com/manuals/cobaltstrike/current/userguide/content/topics/artifacts-antivirus_artifact-kit-main.htm); [Havoc Agent](https://havocframework.com/docs/agent); local `docs/LOADER_AV_OPSEC_PLAN.md`).

## Prioritize a Loaders MVP then guidance, not a crypter

Peer platforms prove operators need a packaging surface **beyond Generate**. Cobalt Strike’s Artifact Kit rewires Attacks → Packages; Mythic uses wrapper payload types and Donut build parameters; Nighthawk markets NHLoader/stego/stager kits as first-class products ([HelpSystems Artifact Kit](https://hstechdocs.helpsystems.com/manuals/cobaltstrike/current/userguide/content/topics/artifacts-antivirus_artifact-kit-main.htm); [Mythic Building Payloads](https://docs.mythic-c2.net/message-flow/building-payloads); [Nighthawk About](https://nighthawkc2.io/about/)). Upstream Sliver UI has Implants generation but **no Loaders section**; this fork already has `POST /api/shellcode/rdi` without a dedicated page and has not wrapped encoder RPCs ([9Insomnie/sliver_ui](https://github.com/9Insomnie/sliver_ui); `docs/LOADER_AV_OPSEC_PLAN.md`).

| Priority | Deliverable | Why |
|---|---|---|
| **P0 MVP** | `/loaders` under Payloads: Source (shared/shellcode build or upload) → Transform (optional RDI; Encoder SGN/XOR/XOR_DYNAMIC; arch; iterations; bad chars) → Output (download, size, SHA256) | Closes Artifact-Kit/wrapper gap; RDI API exists |
| **P0 MVP** | Backend `GET /api/shellcode/encoders`, `POST /api/shellcode/encode`; expose `SGNEnabled` on shellcode generate | Native Sliver RPCs; generate-time and post-encode paths |
| **P0 MVP** | Implants banner + row actions “Send to Loaders” / RDI / Encode | Continues pipeline after generate |
| **P0 MVP** | Persistent disclaimer + layered checklist linking `/http-c2` and session inject/sideload | Matches CS “kit fails” and Havoc external-loader stance |
| **P1** | OS-filtered checklists: local-inject, rdi-dll, sideload naming, service hygiene, Linux memfd/`LD_PRELOAD` | Operators need Win≠Linux guidance |
| **P1** | Encoder presets (light/noisy); before/after hash/size | Reduces mistakes; build feedback peers show |
| **P1** | Stage listeners UI + `GenerateStage` / custom `.woff` stage-0 templates (hide-console default) | Native Sliver staging; shrinks first drop vs multi-MB Go PE |
| **P2** | Exportable lab stub “loader project” markdown/sources; external tools appendix (Donut CLI, MacroPack, custom loaders) | Arsenal-like without claiming FUD |
| **P2** | Optional startup persistence toggles on stubs (Run / schtask / LNK); service format already on Implants | Operator-requested; **off by default** + cleanup copy |
| **P3 optional** | Named artifact store / transform job history | Teamserver-style storage; product decision |
| **P3 optional / high-risk** | Watchdog or “re-fetch if dead” dual-artifact template | AV-kill recovery needs separate survivor; EDR-noisy |
| **Non-goal** | Commercial crypter, PE infection GUI, stego stager, CET stack masking, silent AV auto-heal, guaranteed bypass language | Outside Sliver RPC or dishonest UX; high review bar |

Required page copy must state that **Obfuscate and Evasion are compile-time aids**, **SGN/XOR only mutate bytes**, behavioral EDR still hunts injection and unbacked memory, layered OPSEC is required, and **guaranteed evasion is impossible**—authorized lab / red-team use only (`docs/LOADER_AV_OPSEC_PLAN.md` §7; [Havoc Agent](https://havocframework.com/docs/agent)). Suggested English banner: *Obfuscate and Evasion are compile-time implant options. They are not an antivirus or EDR bypass. Shellcode encoders (SGN/XOR) only transform bytes. Expect detection unless you also layer HTTP C2 camouflage, in-memory delivery, and environment-appropriate host artifacts. No UI option can guarantee evasion.* Ship the same structure in `zh.ts` per project i18n rules. Feature success metric: **operators complete a correct multi-stage package with fewer mistakes**, not “0 detections on VirusTotal.”

## Addendum: stage-0, AV-kill recovery, startup, background

Operator follow-up ideas (authorized lab / red-team only) map onto Sliver’s staging model and persistence tradecraft—with honesty constraints.

**Stage-0 downloader (fetch matching payload → execute).** Sliver’s supported chain is profile (`--format shellcode`) → `stage-listener` (TCP or HTTP/S, optional AES/RC4) → small stager that pulls stage-2 and runs it in memory. HTTP stages are served for any URI ending in `stager_file_ext` (default `.woff`). `generate stager` / `GenerateStage` wraps MSFvenom-style tiny shellcode; production OPSEC usually prefers a **custom** WinInet/WebClient/memfd stub because stock MSF stagers are heavily signatured ([Sliver Stagers](https://sliver.sh/docs/?name=Stagers); [Breuker](https://dominicbreuker.com/post/learning_sliver_c2_06_stagers/); [BallisKit](https://blog.balliskit.com/tutorial-sliver-c2-with-balliskit-macropack-and-shellcodepack-452e94c24b19)). This UI fork only exposes a dead `POST /api/msf/stage` stub today; product work is wiring `StartTCPStagerListener` / `GenerateStage` and shipping custom stage-0 templates beside Loaders (`docs/LOADER_AV_OPSEC_PLAN.md` §4.3, Phase 6). Keep staging host separate from long-haul C2 when infra allows.

**AV-kill auto re-download.** A killed implant cannot resurrect itself. Re-fetch-after-kill requires a **second survivor** (schtask/Run/WMI/watchdog) that still has code execution and usually re-hits the staging URL—an integration problem, not a missing implant checkbox. That pattern is high-signal for EDR (persistence creation + periodic download + RWX). UI should document recovery as rotate-stage-URL / rebuild / re-deliver, and only offer watchdog or “persist the stager” templates behind explicit opt-in and cleanup notes—never as a silent default (`docs/LOADER_AV_OPSEC_PLAN.md` §4.4).

**Startup persistence toggle.** Sliver generate exposes **service** format for Windows service binaries; it does not expose a first-class “add Run key” flag. Operator-facing toggles belong on **loader/stage-0 stubs** (HKCU Run, schtasks ONLOGON, Startup LNK) or as post-session helpers (registry / execute / SharPersist), always **off by default**, with MITRE labels and engagement-close cleanup text ([Hackers Arise persistence](https://hackers-arise.com/sliver-command-and-control-c2-building-a-persistent-c2-part-4/); T1547 / T1053 / T1543).

**Auto-background.** Console flash is a loader packaging issue: Windows stubs use `ShowWindow(SW_HIDE)` or GUI subsystem; .NET stubs use Windows Application output type; service format is inherently headless; Linux “daemonize” inside Go implants has been historically fragile. Default **hide console on** for release EXE stubs; do not equate hidden window with EDR evasion ([Breuker custom C++ stager](https://dominicbreuker.com/post/learning_sliver_c2_06_stagers/)).

## Addendum: encrypt-at-rest then decrypt in memory

**Operator mental model** (“encrypt beacon on disk → AV hash misses → decrypt in RAM → execute”) is **half right**. Ciphertext defeats exact hashes and many plaintext string YARA hits on the **inner** implant (MITRE T1027 / T1027.013). It does **not** defeat stub signatures, entropy/packer heuristics, sandbox detonation of decrypt→alloc→exec, or behavioral EDR / memory scanners after plaintext appears ([Fortbridge 2025](https://fortbridge.co.uk/research/reforging-sliver-how-simple-code-edits-can-outmaneuver-edr/); [Elastic ETW call stacks](https://www.elastic.co/security-labs/threat-command/doubling-down-etw-callstacks); [Sandfly bincrypter](https://sandflysecurity.com/blog/detecting-bincrypter-linux-malware-obfuscation)).

**Operators do use this** as table-stakes packaging: Donut (incl. Chaskey / entropy=3), ScareCrow, PEzor, Nimcrypt2, ShellcodePack, Cobalt Strike Artifact Kit XOR templates, Mythic wrappers, and Sliver AES-staged shellcode—seen in Microsoft Bumblebee→Sliver, HarfangLab Donut+Sliver, and Hunter’s Ledger ScareCrow+Donut+Sliver chains ([Microsoft Sliver lining](https://www.microsoft.com/en-us/security/blog/2022/08/24/looking-for-the-sliver-lining-hunting-for-emerging-command-and-control-frameworks/); full synthesis in [`reports/Sliver encrypt at rest loaders.md`](../reports/Sliver%20encrypt%20at%20rest%20loaders.md)).

**Sliver native map:** `generate` does **not** encrypt EXE/shared/service files. Windows **shellcode** can use Donut module encryption (`--shellcode-entropy 3`) and SGN/XOR self-decoders; **stage-2** can be AES-CBC or RC4 via stage tooling (stager must decrypt). True PE/DLL crypters remain **external**.

**Sliver UI decision:** ship under **Loaders** (stage AES + decrypt stubs first; optional AES lab stub export; external-tools checklist always). Reject an Implants “encrypt payload = FUD” checkbox and in-UI Donut CLI shell-out. Keys/IVs show-once, never UI DB. See `docs/LOADER_AV_OPSEC_PLAN.md` §4.7.

## Conclusion

The decisive product insight is architectural, not checkbox-deep: **traffic OPSEC and payload OPSEC are siblings**, and this UI already owns the first while leaving the second as a raw download. Wiring RDI plus encoders into `/loaders`, adding **stage-0 listeners**, deep-linking Implants, filtering Windows versus Linux transforms, and refusing FUD language (including silent AV auto-heal) turns Sliver UI into a delivery **workstation** that matches how operators actually recover when stock EXE burns—without pretending to outrun Elastic call stacks or Defender cloud reputation. What changes going forward is the default operator path: generate **beacon shared/shellcode** against a customized HTTP profile, stage or transform in Loaders, execute via sideload or in-memory tools with a checklist gate, optional persistence/background only when explicitly chosen, and treat external custom loaders as the advanced layer rather than as a missing checkbox on Implants.
