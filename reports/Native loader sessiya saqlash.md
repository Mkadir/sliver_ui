# C wrap sessiyani saqlamaydi

Operator da’vosi asosan to‘g‘ri: Microsoft Defender callback dan keyin sessiyani o‘ldirsa, joriy Go wrapning XOR, unique SHA-256, RWX, CreateThread yo‘q, HAL9TH, 2 GiB RAM va 1.8 soniya sleep qatlami allaqachon sarflangan. Decrypt dan keyin inbox MDAV shu PID dagi **16–30 MB Go Sliver** ni o‘qiydi — `sliverpb`, protobuf RPC nomlari, `Go buildinf` va `Behavior:Win32/CommandAndControl.*!ml`; `interactive` yangi fayl emas, **shu PID ichidagi goroutine**. Shunga qaramay til almashtirishning ishi bor: Formidable/Praetorian `Wacatac.B!ml` / `gopclntab` **unsigned Go stub PE** ga tegadi, xotira YARAga emas. CRT-free MinGW C (shu hostda bo‘sh `WinMain` **~13 KiB**, xuddi shu 3 baytlik PIC Go wrap **~1.56 MiB**) shu stub sinfini tashlaydi. C# yomonroq: `Assembly.Load` AMSI; NativeAOT Linuxdan `win-*` chiqarmaydi; self-contained **~71 MB**. C++ bu hostda `g++` yo‘q, foydasi yo‘q; `zig cc` uchinchi til emas, arm64 zaxira toolchain. Jonli sessiya 2025 qog‘ozlarida **implant protobuf/string tozalash** (garble qilmaydi) plus **disk `LoadLibrary` DLL** (Fortbridge). Unbacked `VirtualAlloc`+CALL stock PIC baribir flag. Mahsulot: C wrap `windows/amd64` va `windows/386`; `windows/arm64` da Go wrap yoki rad; mingw yo‘q bo‘lsa **503**. C CALL stock `sliverpb` sessiyani saqlamaydi.

## Callback dan keyin Defender wrap hashini emas, sliverpb ni o‘qiydi

Callback wrap PEning **ishga tushishiga ruxsat** berilganining dalili, implantning ko‘rinmasligining emas. Inbox Microsoft Defender Antivirus (`MsMpEng`, MDE litsenziyasisiz Active) ishga tushgan tahdidni to‘xtatadi: xotira skaneri **client** funksiya, cloud ustuni N/A; client behavioral blocking process tree ni cloud ML ga yuboradi va **running artifact** ni block qiladi, jumladan C2 ga murojaat (`Behavior:Win32/CommandAndControl.*!ml`). MDE (`MsSense`) portal va EDR-in-block-mode qo‘shadi (default off); `OnboardingState=0` lab qutisi ham 1117 bilan jonli implantni o‘ldirishi mumkin ([Advanced technologies of MDAV](https://learn.microsoft.com/en-us/defender-endpoint/adv-tech-of-mdav); [MDAV in Windows](https://learn.microsoft.com/en-us/defender-endpoint/microsoft-defender-antivirus-windows); [Client behavioral blocking](https://learn.microsoft.com/en-us/defender-endpoint/client-behavioral-blocking); [Behavioral blocking and containment](https://learn.microsoft.com/en-us/defender-endpoint/behavioral-blocking-containment)).

Immersive: packing qanday bo‘lmasin, **butun Go binary xotiraga ochiladi**, o‘rtacha **~16 MB**. File YARA `sliverpb` + `github.com/bishopfox/` + PE magic; xotira qoidasi faqat **`sliverpb`**, chunki header offset dump da yiqiladi. Fortbridge stock implantlarda Defender-oriented ASCII: `DllUnregisterServer`, `GetJitter`, `VoidFunc`, `AddTunnel`, `GetIsIOC`, `Go buildinf:`; hajm **~30 MB** gacha; sleep mask yo‘qligi idle YARA ni oson qiladi. Elastic `Multi_Trojan_Sliver` `scan_context = "file, memory"`: `ScreenshotReq`, `HTTPSessionInit`, `RequestResend`, `GetPrivInfo`, `github.com/bishopfox/sliver/protobuf`. Garble protobuf metodlarini o‘zgartirmaydi; Cyb3r-Monk “several Defender AV signatures detecting these strings”; #1760 2026-01 da yopilgan, lekin Elastic qoidalari 2026-11 da ham o‘sha satrlarni ushlaydi — stock 1.7.x ni toza deb o‘qimang ([Immersive: Detecting Sliver C2](https://www.immersivelabs.com/resources/c7-blog/detecting-and-decrypting-sliver-c2-a-threat-hunters-guide); [Fortbridge: Reforging Sliver](https://fortbridge.co.uk/research/reforging-sliver-how-simple-code-edits-can-outmaneuver-edr/); [Multi_Trojan_Sliver.yar](https://github.com/elastic/protections-artifacts/blob/main/yara/rules/Multi_Trojan_Sliver.yar); [sliver#1760](https://github.com/BishopFox/sliver/issues/1760)).

`interactive` / UI Open Session **yangi implant generate qilmaydi**. Rasmiy tutorial: session loop **shu beacon jarayonida goroutine**. UI `OpenSessionFromBeacon` `C2S: []`, `Delay: 0`. Yangi PE faqat `migrate` / `execute-assembly` / `execute-shellcode` / `sideload` da — Microsoft 2022 dan beri hujjatlagan `VirtualAllocEx` → `WriteProcessMemory` → `VirtualProtectEx` → `CreateRemoteThread`, default qurbon `notepad.exe`, GetSystem → `spoolsv.exe`. Stock `interactive` fork&run emas; ASR “Office injecting” Word/Excel uchun. Sessiya o‘lsa, odatda **shu PID** o‘ladi — beacon ham ketadi ([Beacons vs Sessions](https://sliver.sh/tutorials/?name=2+-+Beacons+vs+Sessions); [Hunt & Hackett](https://www.huntandhackett.com/blog/hunting-for-a-sliver); [Sliver lining](https://www.microsoft.com/en-us/security/blog/2022/08/24/looking-for-the-sliver-lining-hunting-for-emerging-command-and-control-frameworks/); [ASR rules](https://learn.microsoft.com/en-us/defender-endpoint/attack-surface-reduction-rules-reference)).

Unique hash SmartScreen/BAFS da **noma’lum** kalit, ishonch belgisi emas; cloud PE xususiyat, emulyatsiya, detonation va behavior bilan sinflaydi. ## Wacatac.B!ml unsigned Go stub PEga tegadi, xotira YARAga emas

`Wacatac.B!ml` Microsoft **statik PE-ML** oilasi (`!ml` = klassifikator, bayt imzo emas). Formidable (2026-05): zararsiz Wails 3 + Go 1.25 GUI `Trojan:Win32/Wacatac.B!ml`; to‘rt VT sandbox **0 dynamic**; VersionInfo, manifest, `-s -w` ni tashlash, reproducible `-buildid`, NSIS — ball o‘zgarmadi. Tashxis: klassifikator **Go PE shakli** ni (katta `.text`, `gopclntab`, `runtime.morestack_noctxt` / `runtime.gcWriteBarrier`, statik, CRT yo‘q) ~2020 dan beri Go malware hajmi (Sliver ham) tufayli ijobiy belgi qilgan. Xuddi shu mahsulot Electron da flag olmadi. Qolgan g‘oya: **C/Win32 launcher + Go `c-shared` DLL** ([Formidable: Wacatac va Go](https://formidable.tools/posts/defender-wacatac-go-binary/)).

Praetorian (2026-05): Go hitlar `Wacatac.B!ml` / `ML.Attribute.HighConfidence`; `-s -w` **oshirdi**; ML `gopclntab` ga og‘irlik beradi (hello-world ~2.5 MB, ~100 KB runtime-only jadval — “kichik stripped malware” shakli). Katta “ghost profile” Microsoft Wacatac ni **~95% dan ~20%** ga tushirdi; nomlarni butunlay olib tashlash CrowdStrike/Symantec ni darhol urdi. Soxta MSVC Rich header **yomonlashtirdi** (“toolchain bilan jang qilmang”). Cloud ML lokal `MpCmdRun` dan agressivroq; Wacatac taxminan kunlik qayta o‘qitiladi. Keyingi tadqiqot: asbob manbasini o‘zgartirmasdan tashqi Go/WASM — ya’ni **stub ni yashirish**, implantni emas ([Praetorian: Adversarial Oracles](https://www.praetorian.com/blog/llm-edr-signature-reduction/)).

Joriy sliver-ui Windows stub aynan shu shakl: `GOOS/GOARCH CGO_ENABLED=0`, `-s -w` (Praetorian yomonlashtirgan flag), unique `-buildid`, yuqori-entropy XOR `cfg.dat`, Go runtime IAT da `kernel32.dll` / `VirtualAlloc` / `CreateThread`. `Wacatac` / `gopclntab` **diskdagi wrap PE**; Fortbridge `Go buildinf:` esa **implant ASCII** — boshqa detektor. Elastic `Multi_Trojan_Sliver` `gopclntab` ni tilga olmaydi. Tiny C host `VirtualAlloc` qilib stock PIC ni CALL qilsa ham `sliverpb` / `ScreenshotReq` / `GetJitter` **shu PID ning private executable xotirasida** qoladi. Fortbridge ishlagan yo‘l “C host + stock PIC” emas: **manbada tozalangan implant DLL + diskdan `LoadLibrary`**, MEM_IMAGE. Unbacked PIC da implant Go `LazyDLL` → `LoadLibraryExW` Elastic **“Network Library Loaded from Unbacked Memory”** ni tetikladi — bu chaqiriq **stub tilidan emas**, PIC dan ([Elastic unbacked network-module](https://github.com/elastic/protections-artifacts/blob/main/behavior/rules/windows/defense_evasion_network_module_loaded_from_suspicious_unbacked_memory.toml); [Upping the Ante](https://www.elastic.co/security-labs/upping-the-ante-detecting-in-memory-threats-with-kernel-call-stacks)).

Shuning uchun til almashtirish **birinchi tushish PE-ML** nazorati: `gopclntab` yo‘qoladi, ikkinchi Go runtime process **image** sifatida ketadi. Dual-Go narxi hozir: stub Go (mapped image) plus implant Go (private RWX). C `VirtualAlloc` host faqat birinchisini olib tashlaydi. Microsoft `Wacatac` og‘irliklarini e’lon qilmaydi; “C Wacatac ni qochadi” Go-shakl dalilidan **xulosa**, vendor bayonoti emas. Trapmine Formidable bare EXE da generic unsigned ML; kichik unsigned C ham generic ML ga tushishi mumkin — miqyosi noma’lum. 2025–2026 da “shu 200 qatorlik MinGW C vs sliver-ui Go stub” A/B yo‘q.

## CRT-free MinGW C birinchi; C# AMSI qo‘shadi; zig cc til emas

Wrap — operator yuklab oladigan **host-compile Windows PE**, ichki BishopFox Sliver (Go) emas. Compile Linux da, `POST /api/loaders/build`. Frontend `exeLoaderStub.ts` faqat XOR; in-tree `loader.c` yo‘q. PEzor native yo‘li ham **C** `loader.c` ([PEzor](https://github.com/phra/PEzor)).

C vs C++: CRT-free MinGW (`-nostdlib -fno-builtin -mno-stack-arg-probe -Os -s -mwindows -lkernel32`) IAT ni `KERNEL32.dll` ga qisqartiradi; `-nostartfiles` compiler builtin orqali `msvcrt.dll` `memset` ni jim tortishi mumkin ([CRT-free 2023](https://nullprogram.com/blog/2023/02/15); [GCC MinGW `-mwindows`](https://gcc.gnu.org/onlinedocs/gcc/Cygwin-and-MinGW-Options.html)). Shu Kali hostda `x86_64-w64-mingw32-gcc` / `i686-w64-mingw32-gcc` (GCC 15-win32) bor; **`x86_64-w64-mingw32-g++` yo‘q**. Bo‘sh `WinMain` `-s -Os -fno-ident -Wl,--gc-sections -mwindows` **13 312 bayt**; `VirtualAlloc` + `xor eax,eax; ret` **13 824**; `-nostdlib` `WinMainCRTStartup` + `-lkernel32` **3 584 bayt**, faqat `KERNEL32.dll`. Xuddi shu 3 baytlik PIC Go wrap **1 559 040** (amd64) / **1 484 800** (386) / **1 492 480** (arm64) — ~120×. Default MinGW CRT `msvcrt.dll` + `Mingw-w64 runtime failure:` + CRT `VirtualProtect` ni hatto chaqirmasa ham qoldiradi; `-static` `msvcrt` ni olib tashlamaydi. C++ `iostream` MinGW da yuzlab KB + `libstdc++` DLL; `-fno-exceptions -fno-rtti` locale ni o‘chirmaydi. MSVC `/MT` Linux hostda yo‘q. C++ ni “C plus `//`” qilib yozish C dan yaxshi emas; `g++-mingw-w64` ni stub uchun qo‘ymang.

C# **yomonroq** native Sliver PIC loader uchun. AMSI PowerShell/WSH/Office va **“.NET Framework 4.8+ (barcha assembly)”**; native Go/C EXE AMSI host emas ([AMSI on MDAV](https://learn.microsoft.com/en-us/defender-endpoint/amsi-on-mdav); [AMSI portal](https://learn.microsoft.com/en-us/windows/win32/amsi/antimalware-scan-interface-portal)). CoreCLR `AmsiScanBuffer` ni **faqat in-memory** `Assembly.Load(byte[])` da chaqiradi; disk load allaqachon Defender da ([dotnet/runtime `amsi.cpp`](https://github.com/dotnet/runtime/blob/main/src/coreclr/vm/amsi.cpp); [BorderGate](https://www.bordergate.co.uk/assembly-load-amsi/)). `AmsiScanBuffer` patch `Win32/AMSI_Patch_T.B13` / `Behavior:Win32/AMSI_PATCH_T.B12` — mahsulot rad etgan Donut Bypass=3 sinfi ([sliver#1759](https://github.com/BishopFox/sliver/issues/1759)). Shu hostda `dotnet` SDK **6.0.400**; `dotnet publish -r win-x64 --self-contained` **227 fayl, 71 386 826 bayt** (`coreclr.dll`, `clrjit.dll`, `hostfxr`). `PublishAot=true` SDK 6 da **e’tiborsiz**. NativeAOT **cross-OS emas** — Windows (yoki matching-OS) C++ linker; Linux UI hostdan `win-*` chiqmaydi; stub **~4–15 MB**, 13 KiB C emas ([Native AOT](https://learn.microsoft.com/en-us/dotnet/core/deploying/native-aot/); [Native AOT cross-compile](https://learn.microsoft.com/en-us/dotnet/core/deploying/native-aot/cross-compile)). C# faqat payload .NET assembly bo‘lganda (Donut/execute-assembly) mantiqiy — u holda ham loader **native C** qoladi.

Zig **til** sifatida C ni yengmaydi (std, rewrite). **`zig cc`** bir ~55 MiB toolchain bilan **shu C** ni amd64/386/**arm64** Windows ga chiqaradi ([Zig overview](https://ziglang.org/learn/overview); [llvm-mingw](https://github.com/mstorsjo/llvm-mingw) — GCC Windows on ARM ni **qo‘llab-quvvatlamaydi**). Shu hostda `zig` yo‘q, `aarch64-w64-mingw32-gcc` yo‘q, Nim yo‘q. Nim OffensiveNim ~50 KB GC + ommaviy tool imzo; Rust `no_std` Windows target o‘rnatilmagan. Public Nim/Zig/Rust “Defender ni yengdi” postlari odatda syscall/unhook/AMSI — ScareCrow/Freeze sinfi, **tashqarida**.

## Jonli sessiya disk LoadLibrary va tozalangan implant talab qiladi

Til wrapning **yetkazib berish** deteksiyasini o‘zgartiradi. Donut PIC map qilgach, Defender/Elastic **plaintext Go implant**, unbacked (yoki image-backed) xotira, `LoadLibraryExW` call-stack, default HTTP va post-ex ni ko‘radi. C stub stock `sliverpb` ni CALL qilsa, Fortbridge **samarasiz** deb topgan tarmoq: “encrypted implant in a loader… self-injection or process hollowing… **proved ineffective**” against Elastic **and** Defender ([Fortbridge](https://fortbridge.co.uk/research/reforging-sliver-how-simple-code-edits-can-outmaneuver-edr/); [Sliver AV evasion out of scope](https://sliver.sh/docs?name=Anti-virus+Evasion)).

Fortbridge ketma-ketligi: protobuf rename + regen; `maxConnectionErrors` inline; Donut Bypass **3→1** (default AMSI patch og‘ir imzo); keyin ham HTTP beacon `NewLazyDLL()` → `LoadLibraryExW` → Elastic unbacked network-module. Pre-load yordam bermadi; HWBP hook **o‘tmadi**; module stomping **~30 MB** da tashlandi. Ishlagan yo‘l: tozalangan DLL ni **shu papkadan `LoadLibrary`**, export, yangi thread. Kernel EXE/DLL ni `MEM_IMAGE` qiladi; `VirtualAlloc` PIC `MEM_PRIVATE` / unbacked. Reflective load 2017 dan beri “RWX, mos DLL yo‘q” ovlanadi ([Amethyst: MEM_IMAGE](https://amethyst.systems/blog/posts/mimicking-the-windows-executable-loaders-memory-allocation/); [Microsoft 2017 reflective DLL](https://www.microsoft.com/en-us/security/blog/2017/11/13/detecting-reflective-dll-loading-with-windows-defender-atp/); [Almond: unbacked = shellcode](https://offsec.almond.consulting/evading-elastic-callstack-signatures.html)). Signed EXE + **implantning o‘zi** disk DLL — unbacked `wininet`/`ws2_32` call-stack ketadi. Signed EXE + **kichik stub DLL** keyin VirtualAlloc+Donut — implant baribir unbacked; sideload foydasi stage-0. Disk load **string-clean siz** DefenderYara ASCII da yiqildi; MDAV xotira skaneri MEM_IMAGE ni “o‘tkazib yuboramiz” deb hujjatlamagan. Built-in buyruqlar keyin ham Elastic behavior.

HTTP C2 kengaytmalari (`stager` **`.woff`**, poll **`.js`**, session **`.php`**, close **`.png`**) **generate da** `http-c2.json` dan pishiriladi; loader XOR qayta yozmaydi. Custom profile — generate-time, protobuf fork talab qilmaydigan kam post-callback dastaklardan. `interactive` `.php`+`.js` long-poll ni isitadi. moloch: server JARM random lekin operator tanlamaydi; mTLS Go fingerprint; Windows da `?driver=wininet` client fingerprint, hook osonroq ([HTTPS C2](https://sliver.sh/docs/?name=HTTPS+C2); [sliver#1809](https://github.com/BishopFox/sliver/issues/1809)). Inbox MDAV NIS ning `.woff/.php` ni o‘ldirishini Protection History siz da’vo qilmang; `Behavior:Win32/CommandAndControl` host xatti-harakati.

Sleep mask **stubda yo‘q**. Stock Sliver Ekko ship qilmaydi; PR #1805 (2026-07 force-push) merge emas, hang/deadlock, uyg‘onishda RWX. moloch: Go runtime tufayli qiyin; runtime ni pauza qilmasdan bir funksiyani shifrlash panic. C CALL Donut **beacon sleep loop ni ega emas**; tashqi XOR Go scheduler ni buzadi. Interactive **uyg‘oq** (long-poll) — sleep-encrypt operator ishlayotgan oynani yopmaydi. Elastic `execute_fluctuation` / `unbacked_rwx` protect-flip ovlaydi ([#1171](https://github.com/BishopFox/sliver/discussions/1171); [#1805](https://github.com/BishopFox/sliver/pull/1805)).

2025–2026 omma yozuvlari ikki sinf: **(A)** unique stage-0 / packer, stock implant (bytebl33d C++/C# + Donut `-b 1 -e 3` + HTTP json — callback, Elastic unbacked yo‘q; BallisKit ShellcodePack — “stage-2 in memory still caught”) va **(B)** Sliver manba fork (Fortbridge `sed`, slivercloak protobuf/branding/donotamsi, better-sliver — sleepmask bug uchun olib tashlangan). Faqat (B) post-callback xotira YARA ni o‘zgartiradi. sliver-ui stock gRPC GUI; (B) **tashqarida**, client/server juftligi fork bilan mos bo‘lishi shart ([bytebl33d](https://bytebl33d.github.io/blog/sliver-evasion/); [BallisKit](https://blog.balliskit.com/tutorial-sliver-c2-with-balliskit-macropack-and-shellcodepack-452e94c24b19); [slivercloak](https://github.com/thelikes/slivercloak); [better-sliver](https://github.com/gsmith257-cyber/better-sliver-package); [DFIR Report](https://thedfirreport.com/2024/08/12/threat-actors-toolkit-leveraging-sliver-poshc2-batch-scripts/)).

RW→**RX** (`PAGE_EXECUTE_READ` 0x20) `unbacked_rwx` ni yumshatadi; Donut/SGN self-mod **RWX** (`0x40`) talab qiladi; PEzor `-rx` SGN bilan nomuvofiq ([Memory protection](https://learn.microsoft.com/en-us/windows/win32/memory/memory-protection-constants); [PEzor README](https://github.com/phra/PEzor)). Direct syscall in-tree — Elastic `direct_syscall`, public stublar eskiradi, Freeze sinfi, **yo‘q**. Donut Bypass=1 mahsulotda bor; AMSI/ETW byte patch, defendnot, ScareCrow, in-tree Donut CLI, BYOVD qayta ochilmaydi.

## Mahsulot: amd64/386 da C wrap, arm64 da Go yoki 503

Linux UI host compile qiladi; operator Windows qutisida compile qilmaydi. Shu Kali 2026.1: mingw gcc amd64/386 **bor**, Wine 10 **bor**, `g++-mingw` / zig / llvm-mingw / `aarch64-w64-mingw32-gcc` **yo‘q**. `LookPath` compiler binary (`x86_64-w64-mingw32-gcc`), metapackage nomi emas. Xato matni: `apt install gcc-mingw-w64-x86-64` (386 uchun `gcc-mingw-w64-i686`) ([Debian gcc-mingw-w64-x86-64](https://packages.debian.org/sid/gcc-mingw-w64-x86-64); [mingw-w64 downloads](https://www.mingw-w64.org/downloads/)). Mingw yo‘q: native-C Windows uchun **HTTP 503** (yetishmaydigan host dependency), 500 emas; ZIP + “Windows da compile qiling” **yo‘q**. `windows/arm64` ni mingw yo‘qligi uchun bloklamang: Go wrap allaqachon 1.49 MiB PE chiqaradi; UI copy “Go PE-ML qoladi”. Operator aniq “native C” so‘rasa va toolchain yo‘q — 503. JSON da `cflags`/`ldflags` **400**. Argv fixed; `MkdirTemp("sliv-loader-*")`; user satrlarni shell ga `sprintf` qilmang. Linux/Darwin wrap Go da qoladi.

Ikki operator yo‘li, **halol yorliq**. **PIC yo‘li** (bugungi wrap, til almashuvi): `format=shellcode` XOR → RW alloc → decrypt → protect **RX agar encoder NONE, RWX agar SGN/Donut yozadi** → same-thread CALL → hang. Yordam beradi **stub PE-ML**. Jonli sessiya da’vo qilmaydi. **Disk DLL yo‘li** (Fortbridge shakli): `format=shared`, RDI/unbacked PIC **emas**; kichik C EXE (yoki operator signed host) yonidagi DLL ga `LoadLibraryW`; Sliver `DllMain` `RunAtLoad=false` da inert — export **StartW** `GetProcAddress` + chaqiriq. Yordam beradi **unbacked call-stack** faqat implant string/protobuf ishi **tashqarida** bo‘lsa. Yorliq: “disk DLL; still unsigned; still needs string-clean implant; not a C PIC trampoline.” Unique hash C da ham hash-IOC: nonce, 4–24 KiB pad, overlay. Hide-console `-mwindows` (subsystem), runtime `ShowWindow` emas. Persist default off (T1547/T1053).

## Conclusion

Til urushi PE-shakl chiptasi: Go wrapni C ga o‘girish `Wacatac` klassifikatorini noto‘g‘ri chelakdan chiqaradi, lekin decrypt qilingan `sliverpb` ni boshqa jarayonga ko‘chirmaydi. Session umri 2025 da **kim gapiryapti** (protobuf/export/`bishopfox`) va **qayerdan gapiryapti** (`MEM_IMAGE` disk DLL vs unbacked CALL) — ikkalasi ham wrap `-buildid` idan tashqarida. PIC yo‘lini C da qayta yozib “nativlashtirdik” desangiz, Fortbridge yiqilgan tarmoqni mahsulot qilasiz; disk-DLL ni C da ochib “sessiya saqlanadi” desangiz, tozalanmagan stock implant YARA sini yashirasiz. Keyingi commit: amd64/386 da CRT-free C, arm64 da Go yoki aniq 503, ikkita yorliq, stock BishopFox ni fork qilmasdan FUD va’da qilmaslik.
