# Our Windows loader: implemented tricks vs detection class

Authorized lab analysis of `/home/cup/Documents/personal/sliv` host-compile loader (`POST /api/loaders/build`). Not a FUD claim.

## Execution path (Windows)

Source generated by `windowsSource()` in `backend/internal/loader/windows.go`, compiled by `Build()` in `build.go` with `GOOS/GOARCH CGO_ENABLED=0`, `-s -w`, optional `-H windowsgui`, unique `-buildid`.

`main()` order:

1. `hideWindow()` — `GetConsoleWindow` + `ShowWindow(0)` + `FreeConsole` if hide-console.
2. `enoughRAM()` — `GlobalMemoryStatusEx`; exit if total RAM `< 1 GiB`. Skipped if `SLIV_BG=1`.
3. `pause()` — `Sleep(1800)` then `GetTickCount` delta; exit if elapsed `< 1400` (emulator skip). Skipped if `SLIV_BG=1`.
4. `persist()` — optional HKCU Run / schtasks ONLOGON / Startup copy / all.
5. `run()` — allocate, copy+XOR decrypt, `VirtualProtect` RWX, `jump(code, stack)`.

`run()` memory model (`windows.go`):

- `VirtualAlloc(NULL, rounded, MEM_RESERVE, PAGE_NOACCESS)` then commit RW, else fallback `MEM_COMMIT|MEM_RESERVE` RW.
- Chunked copy of `cfg.dat` into the allocation (not Go heap).
- XOR decrypt in place with `combinedXORKey` (operator key mixed with 16-byte nonce).
- `VirtualProtect(addr, n, PAGE_EXECUTE_READWRITE = 1<<6)` — **stays RWX**.
- `FlushInstructionCache`.
- Second alloc: 8 MiB RW stack; `runtime.LockOSThread`; `debug.SetGCPercent(-1)`; `jump(addr, stk)`.

API names are XOR-encoded as `\xHH` literals and decoded by `ds()` **byte index** (`for i := 0; i < len(enc); i++`). `NameKey` is random per build. Go runtime IAT still contains `kernel32.dll` / `VirtualAlloc` / `CreateThread` strings; those cannot be stripped.

## Trampoline (critical)

`jump_windows_amd64.s` in `source.go` `jumpAsm()`:

```
CALL AX
MOVQ R12, SP
POPQ R12
RET
```

If the PIC **returns**, control returns to Go `run()` → `main()` → **process exit**. Linux trampolines `exit_group` after CALL; Windows restores the Go stack and returns.

Sliver Windows `format=shellcode` is **Donut of a PE** (`DonutShellcodeFromFile`). Default Donut: `Thread=1` (run EXE entry as a thread), `ExitOpt=1` (exit **thread**, not process). The Donut stub is designed to **return to the caller** after starting the implant thread. Our host then exits and the OS tears down that thread.

This is a **correctness bug** for symptom 1 (run EXE, no session), independent of Defender.

BishopFox: “If the process is terminating you may have a bug in your loader code” ([sliver#1410](https://github.com/BishopFox/sliver/issues/1410)). Donut `-x 3` (block indefinitely) is the matching generator-side option; our stub should **not return** after `jump`.

RDI path (`handlers_loaders.go`): full MZ+PE/DLL → `ShellcodeRDI` then same CALL. sRDI DllMain often starts work and **returns** — same process-exit bug.

## Uniqueness (hash only)

`mintUniqueness`: 16-byte nonce mixed into XOR, 4–24 KiB `n.bin` pad, random `NameKey`, Go `-buildid`. SHA-256 always changes. **Hash-IOC only.** Cloud ML / sandbox still sees a new unsigned Go PE with high-entropy embed.

## Grade of each trick

| Trick | Detection class it can affect | Cannot affect |
|---|---|---|
| XOR embed + nonce | Exact file hash, some static strings in blob | Live memory after decrypt; ML on PE; behavior |
| Unique buildid / n.bin | Exact hash | Sandbox, ML, memory YARA |
| `ds()` API name XOR | Plaintext `VirtualProtect`/`schtasks` in **our** source | Go runtime IAT; kernel callbacks |
| PAGE_NOACCESS → RW → decrypt | Some heap scanners / emulator that never commit | WdFilter on VirtualProtect RWX |
| Skip CreateThread, CALL on private stack | User-mode CRT start-address heuristics | Unbacked executable memory; ETW; implant strings |
| Sleep 1.8s + tick | Short emulators that honor Sleep | Cloud sandbox that skips Sleep or runs longer; live Defender |
| RAM ≥ 1 GiB | Tiny emulator VMs | Real 8+ GiB lab PCs; Defender content process |
| Hide console / windowsgui | User-visible window | EDR |
| Persistence | Reboot survival | Defender; adds T1547/T1053 artefacts |
| RWX (`1<<6`) | Required for Donut/SGN self-mod (moloch #1410) | **Increases** behavioral RWX signal |

## Honest leftovers

- Wine PIC `xor eax,eax; ret` is not a Windows session test.
- Compile success is not a callback; implant still needs a live matching listener.
- Unique hash ≠ VirusTotal 0/70.
- Persistence and hide-console do not stop Defender killing a live implant.
