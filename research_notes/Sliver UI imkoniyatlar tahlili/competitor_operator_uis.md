# Competitor operator UIs (2024–2026) for a Sliver web console

## What interaction patterns do the best operator UIs share (multi-pane, session tabs, graphs, event streams, search, keyboard)?

### Takeaway
Mature C2 consoles converge on a CS/Havoc-style multi-pane workspace: a session table or pivot graph on top, a live event/chat pane, and tabbed bottom consoles for interact / files / processes. Keyboard-first tasking, right-click context menus, privilege highlighting, and a searchable event stream are the shared muscle memory.

### Cited Findings
- Cobalt Strike exposes three primary visualizations — Pivot Graph, Session Table, Target Table — switched from a toolbar or **Cobalt Strike → Visualization**. The Pivot Graph is presented as necessary once Beacon chains go four or five hops deep. Icons encode OS; red + lightning = admin; dashed green = HTTP(S) egress, yellow dashed = DNS; orange arrows = named-pipe/SSH, blue = TCP, red/purple = broken links. Keyboard: Ctrl+Plus/Minus/0 zoom, Ctrl+A select all, Escape clear, Ctrl+C/S/H circle/stack/hierarchy layouts. Right-click a Beacon for post-ex. — [CS User Guide: Session and Target Visualizations](https://hstechdocs.helpsystems.com/manuals/cobaltstrike/review/userguide/content/topics/ui_session-target-visualizations.htm)
- CS Process Browser is a dedicated Explore tab: process tree with the current Beacon process highlighted yellow; buttons to impersonate, screenshot, or keylog from selected PIDs. Multi-Beacon process browsers exist so one operator can deploy screenshot/keylog across hosts after sorting by process name. — [CS Process Browser](https://cobaltstrike.com/help-process-browser)
- CS screenshots and keystrokes land in **View → Screenshots** and **View → Keystrokes**, live-updating across all sessions so one operator can monitor while others task. `screenshot` is one-shot; `screenwatch` is continuous until `jobkill`. — [CS Keystrokes and Screenshots](https://hstechdocs.helpsystems.com/manuals/cobaltstrike/current/userguide/content/topics/post-exploitation_keystrokes-screenshots.htm); [CS 4.2 blog](https://www.cobaltstrike.com/blog/cobalt-strike-4-2-everything-but-the-kitchen-sink)
- CS SOCKS is a first-class pivot: **[beacon] → Pivoting → SOCKS Server** or `socks 8080`; SOCKS4/SOCKS5 with optional auth and logging; **View → Proxy Pivots** lists them; traffic is queued as Beacon tasks and stalls while Beacon sleeps. — [CS SOCKS Proxy](https://www.cobaltstrike.com/help-socks-proxy-pivoting)
- CS event log is both operator chat and a notice board (joins, new beacons, sites). Raphael Mudge’s “Red Team Ops with Cobalt Strike – Operations” walkthrough shows tab-complete handles, `/me`-style actions, and highlighted mentions. Logs on disk are organized by date and target IP (`beacon_[session ID].log`, keystrokes, screenshots). Reports merge multiple teamservers onto one clock. — [YouTube: Red Team Ops with Cobalt Strike – Operations](https://www.youtube.com/watch?v=i6tsLWrCiGE); [CS Everything Logs](https://hstechdocs.helpsystems.com/manuals/cobaltstrike/current/userguide/content/topics/blog_let-the-logs-out.htm); [Aggressor events](https://www.cobaltstrike.com/aggressor-script/events.html)
- Havoc’s Qt client (Dracula theme) copies that layout almost 1:1: menus **Havoc / View / Attack / Scripts / Help**; top-left sessions in **Table or Graph**; top-right Event Viewer (operators connect/disconnect, listeners, new sessions); bottom tabbed Teamserver Chat, Listeners, Interact consoles, File Explorer, Process List, Loot, Scripts Manager. Right-click session → Interact opens a bottom tab. Privileged vs unprivileged sessions are color-coded (red ID in table; red boxes + lightning in graph). — [Havoc README](https://github.com/HavocFramework/Havoc/blob/main/README.md); [r1ckyr3c0n Havoc UI 2024](https://medium.com/@r1ckyr3c0n/havoc-c2-framework-part-2-client-user-interface-2024-c029322527f1); [Havoc screenshots](https://github.com/HavocFramework/Havoc/tree/main/assets/Screenshots)
- Havoc was archived read-only on 20 Feb 2026. Treat it as a frozen UX reference, not an evolving product. — [Havoc repo](https://github.com/HavocFramework/Havoc)
- Mythic 4.0 Active Callbacks is a browser equivalent of the CS workspace: virtualized resizable callback table; row/bulk actions (tasking view, lock/unlock, file/process/custom browsers, graph metadata, hide/exit); Tab completes commands and parameters; arrow-key history and **Ctrl+R** reverse history search; task headers show operator, status, comments, tags; workspaces include normal tab, expanded/split layouts, and console-like output. High-integrity callbacks are visually distinguished (`integrity_level` > 2). Operators can edit description and **row color**. — [Mythic 4.0 Active Callbacks](https://docs.mythic-c2.net/version-4.0/operational-pieces/active-callbacks)
- Mythic’s daily operator pages (docs index) are: Browser Scripts, Active Callbacks (including graph/tree), Files, Search, Credentials, Expanded Callbacks, Screencaptures, Event Feed. Search is a case-insensitive grep across callbacks, tasks, files, screenshots, keylogs, tokens, artifacts. — [Mythic Operational Pieces](https://docs.mythic-c2.net/operational-pieces); [Mythic Search](https://docs.mythic-c2.net/operational-pieces/search)
- Mythic 4.0 docs UI itself uses **⌘K** search and **⌘I** assistant — the same command-palette pattern Nighthawk/Siren/Mr-In4inci3le now ship. — [Mythic 4.0 home](https://docs.mythic-c2.net/version-4.0/home)
- Cody Thomas (SO-CON 2024) described Mythic’s collaborative web UI with per-operator login, Admin/Operator/Spectator RBAC, GraphQL API, a morning dashboard of callback counts and failing commands, and browser-script graphs. He stated Mythic is not BloodHound UI: graphs with more than ~50 nodes “may work just fine but it may slow things down.” — [Cody Thomas, Beyond the Shell, SO-CON 2024](https://www.youtube.com/watch?v=_dqiYDkaG7M)
- Nighthawk 1.0 (2026, vendor blog) rebuilt the client in Avalonia for native Windows and Linux; headline QoL is **split consoles side-by-side** (interactive command + Hidden Desktop / second agent / long-running task) so operators stop tab-flicking. 0.3 already added a C2 mesh graph, resizable consoles, moveable pivot nodes, and a **visual command queue with cancel**. Treat theming as marketing; split consoles and command-queue cancel are the operator-facing claims. — [Nighthawk 1.0 Apex](https://nighthawkc2.io/apex/); [Nighthawk 0.3 Automate All The Things](https://nighthawkc2.io/automate-all-the-things/)
- Brute Ratel’s public marketing emphasizes Commander (Qt; v2.2 moved to Qt 6.9), Click Script automation, LDAP Sentinel GUI, MITRE graph, chatbox, command queue, scratchpad, hosted files, autoruns, payload profiler. Detailed Commander UX lives in an offline PDF (`Brute-Ratel-docs.pdf`) not on the public site — so public claims are marketing until corroborated. Third-party writeups describe Operator user admin, Watchlist event log, per-badger daily log rotation, Operator Activity export to CSV with MITRE IDs. — [BRc4 homepage](https://bruteratel.com/); [BRc4 Features page](https://bruteratel.com/tabs/features/); [BRc4 v2.2 Rinnegan](https://bruteratel.com/release/2025/05/15/Release-Rinnegan/); [Chaitin Rivers BRc4 1.4.5 module notes](https://rivers.chaitin.cn/blog/cqj618p0lnedo7thpt80)
- Covenant’s web UI (2019 “Usability Update”, still the public UX baseline) is sidebar-driven: Dashboard, Listeners, Launchers, Grunts, Tasks, Templates, Graph View (P2P listener/grunt graph), Data (creds/indicators/downloads), Users. Grunt interaction offers both a CLI-like Interact tab and a GUI Task dropdown. Spectator-style multi-user is first-class. — [SpecterOps: Covenant Usability Update](https://specterops.io/blog/2019/08/02/covenant-the-usability-update/); [Covenant README](https://github.com/cobbr/covenant)
- Official Sliver GUI (Electron, `sliverarmory/sliver-gui`, public 2026) ships: multiple windows with independent workspace state; Overview topology; Sessions/Beacons dashboards; interaction workspaces with Files/Processes/Environment/Registry/Activity; generation/builds/profiles; jobs/listeners; Loot/Credentials; hosted websites with Monaco editor + loopback preview; dedicated Sliver console + SSH Ghostty tabs; command palette to jump to live sessions/beacons by name; configurable keyboard shortcuts. WireGuard operator configs are recognized but **cannot connect**. Not every upstream command is implemented (parity report). Building from source requires a HeroUI Pro license; prebuilt binaries are on GitHub Releases. — [sliverarmory/sliver-gui README](https://github.com/sliverarmory/sliver-gui)
- Siren (Wails v3 + Svelte) and Mr-In4inci3le (Wails v2) both copy CS/Havoc: table **or** graph agent workspace, split bottom panes, draggable tabs, command palette (`Ctrl+K` on Mr-In4inci3le), live event stream with toasts. — [Gubarz/siren](https://github.com/Gubarz/siren); [Mr-In4inci3le/sliver-gui](https://github.com/Mr-In4inci3le/sliver-gui)

### Inferences
- The winning pattern is **situation + action + transcript in one glance**: (1) who is alive and how they route, (2) a place to type or click a task, (3) a place to see output and team activity. Dashboards are secondary.
- Privilege highlighting (CS lightning, Havoc red ID, Mythic integrity color) is a universal affordance because operators constantly ask “is this SYSTEM?” before the next click.
- Graphs are not decoration when pivots exist: CS’s own docs say chains of 4–5 hops are common and unreadable as a table. A Sliver web UI that only lists sessions will feel unfinished next to Havoc/CS/official sliver-gui/Siren. This fork already has a per-session pivot *tree* (`PivotTab` + `/pivots/graph`); it is not a spatial CS-style graph on the sessions list. — local `frontend/src/components/session/PivotTab.tsx`; local README Sessions section
- Keyboard density is a competitive feature: CS graph shortcuts, Mythic Tab/Ctrl+R, command palettes in Nighthawk/Siren/sliver-gui. Mouse-only web UIs lose operators who live in CS.
- Loot/screenshots/keystrokes belong in **global views**, not only inside one session tab. CS and Mythic both learned this: one operator monitors, others task.
- Mythic’s own author (Cody Thomas) treats large graphs as a performance trap. For a Sliver web console, a bounded pivot graph (official GUI already caps pivot inventory at 500 entries) is the right size; a BloodHound-scale canvas is not.

### Gaps
- No independent 2024–2026 operator survey quantifying which CS panes are used daily vs ignored. Praise is inferred from docs, vendor blogs, and clone UIs.
- Fortra CS 4.13+ user-guide HTML is partially gated (some `hstechdocs.helpsystems.com` paths 403). Pivot Graph page above is from the “review” mirror dated November 2026.
- BRc4 Commander layout cannot be verified from primary public docs; the vendor moved full docs offline.
- Nighthawk `nighthawkc2.io/apex/` DNS failed at one fetch in this pass; 1.0 UI claims are from search snippets of that page and earlier public posts.

## What does Mythic uniquely do well (browser scripting, tags, files, task output, dockerized agents)?

### Takeaway
Mythic is the only widely used open C2 whose *product* is a collaborative web operations database: every payload, command version, task, file, comment, tag, and ATT&CK mapping is queryable. Browser scripts, dockerized payload/C2 containers, GitHub-Actions-style eventing, and (in 4.0) operation chat / AI chat containers are unique. The callback table is good; the graph is secondary to CS/Havoc.

### Cited Findings
- Mythic’s stated differentiator is data modeling: from payload creation it tracks C2 parameters, loaded command versions, who created it, when, and why. Questions like “which payload created this callback?”, “who issued this task?”, “what changed on this host?” are answerable in the UI. Commands map to ATT&CK and appear in matrix and ATT&CK Navigator views. Operators comment on tasks. Global search covers tasking, output, comments, files, credentials, and chat. — [Mythic 4.0 home](https://docs.mythic-c2.net/version-4.0/home); [Mythic home](https://docs.mythic-c2.net/home)
- Architecture: React UI + Go GraphQL server + PostgreSQL + RabbitMQ. Payload types, C2 profiles, translation, webhook, eventing, log, and chat services run in **separate Docker containers**, same host or remote. The Mythic repo itself does **not** host payload types or C2 profiles. A reverse Nginx proxy fronts React UI, per-agent Hugo docs, Hasura GraphQL console, and a Jupyter notebook with Mythic Scripting preinstalled. — [Mythic 4.0 home](https://docs.mythic-c2.net/version-4.0/home); [SpecterOps: Browser Scripting hidden gems](https://specterops.io/blog/2025/08/21/transforming-red-team-ops-with-mythics-hidden-gems-browser-scripting/)
- **Browser scripts**: JavaScript `function(task, responses)` that return structured data so React can render tables, buttons, links, media, graphs, tabs. Defaults import per installed agent; operators can register personal scripts; per-task toggle to raw output. Permanent scripts live in the payload-type container. SpecterOps (Aug 2025) frames this as the “hidden gem” that turns command output into an interactive UI without forking Mythic. — [Mythic Browser Scripts](https://docs.mythic-c2.net/operational-pieces/browser-scripts); [SpecterOps browser scripting](https://specterops.io/blog/2025/08/21/transforming-red-team-ops-with-mythics-hidden-gems-browser-scripting/)
- **Task output (4.0)**: improved streaming, pagination, filtering, completion tracking, single-task deep links. Plain output switches among plaintext, formatted JSON, Markdown, and xterm. Interactive commands use the terminal for keyboard/ANSI while Mythic still records I/O. File-editor protocol commands open a **versioned editor in the response area**. Task states: Creating → Parsing → Submitted → Processing → Processed → Completed (or Error). — [Mythic 4.0 Active Callbacks](https://docs.mythic-c2.net/version-4.0/operational-pieces/active-callbacks)
- **Files**: clip-icon page lists all uploads/downloads by task, who, when, src/dst. Preview first 512KB as string or xxd hex without downloading. Multi-select **Zip & Download**. SHA1/MD5 and parent-task comments on expand. 4.0 adds resumable byte-offset transfers and managed C2-hosted files. — [Mythic Files](https://docs.mythic-c2.net/operational-pieces/files); [Mythic 4.0 home](https://docs.mythic-c2.net/version-4.0/home)
- **Tags / comments / credentials**: task headers expose comments and tags. Operators can edit callback description and row color. Credentials page: view/comment/edit/add. 4.0 “richer credentials” and task references that resolve `@cred` and `@link` immediately before submit (so operators do not paste secrets into command lines). Callback locks coordinate operators and are explicitly *not* a substitute for permissions or API-token scopes. — [Mythic Operational Pieces](https://docs.mythic-c2.net/operational-pieces); [Mythic 4.0 Active Callbacks](https://docs.mythic-c2.net/version-4.0/operational-pieces/active-callbacks)
- **Operations / RBAC**: operations collect operators, payloads, tasks, artifacts, callbacks, files. Roles: global Admin, Operation Admin, Operator, Spectator (read-only). Block lists of forbidden commands per payload type, tied to operators. Invite links (optional) auto-assign operations; uses recorded in the event feed. 4.0 aliases: reusable command/text expansions scoped to payload types or chat containers, import/export. — [Mythic Operators 3.3](https://docs.mythic-c2.net/operators); [Mythic Operators 4.0](https://docs.mythic-c2.net/version-4.0/operators); [Mythic Operations](https://docs.mythic-c2.net/operational-pieces/operations)
- **Event feed vs 4.0 chat**: Event feed (bell icon) is a live log of new callbacks, payloads, logins, errors with resolve buttons. 4.0 **separates** operator conversation into Operation Chat: persistent channels, search, edit/delete own messages, unread state; optional AI chat containers with streamed Markdown, tool-use cards, and **approval cards before write-capable tools**. — [Mythic Event Feed](https://docs.mythic-c2.net/operational-pieces/event-feed); [Mythic 4.0 Operation Chat](https://docs.mythic-c2.net/version-4.0/operational-pieces/operation-chat)
- **Sage (Nov 2026, SpecterOps)**: open-source AI assistant that lives inside Mythic v4 as a native chat container. Conversation mode is read-only; Supervised mode is default-deny with native Mythic approval cards before issuing a task, creating a payload, or adding a credential. First commit April 2025. This is shipped product documentation from SpecterOps, not a sales page, but it is new. — [SpecterOps: Sage](https://specterops.io/blog/2026/11/10/sage-ai-for-assumed-breach-operations-built-into-mythic/)
- **Eventing (playbooks)**: GitHub-Actions-like YAML/JSON/TOML workflows. Triggers include new callback (with `trigger_data` to limit OS/payload), manual, keyword, cron-like. UI shows a step graph, play button, backing file, extra file attachments, and which extra containers must be online. SpecterOps Pantheon (Aug 2025) publishes starter recon YAML for Apollo because official examples were thin. 4.0 adds interactive eventing approvals. — [Mythic Eventing](https://docs.mythic-c2.net/customizing/3.-consuming-containers/eventing); [SpecterOps Pantheon](https://specterops.io/blog/2025/08/15/pantheon-introduction-a-guide-and-script-collection-for-mythic-eventing/)
- **Dockerized agents**: each payload type container holds metadata, agent source, build code, command metadata/code, and browser scripts. C2 profiles are separate containers that translate any wire protocol to Mythic HTTP+JSON so new C2 does not fork the core. Base image includes Python, Go, .NET, even a macOS SDK. — [Mythic Payload Type Development](https://docs.mythic-c2.net/version-2.3/customizing/payload-type-development); [Mythic C2 Development](https://docs.mythic-c2.net/customizing/c2-related-development)
- Mythic 4.0 “what is new” list (shipped in docs, not a sales page): scoped opaque API tokens, operation chat and AI chat containers, operator aliases, task references, richer build/C2 parameters, conditional wrapper compatibility, interactive eventing approvals, resumable file transfers, interactive text editor, richer credentials, managed C2-hosted files, agent-initiated RPC. — [Mythic 4.0 home](https://docs.mythic-c2.net/version-4.0/home)
- Merlin has a first-class Mythic agent port (`MythicAgents/merlin`) using Mythic’s default HTTP profile — evidence that Mythic’s UI is a platform other C2s plug into rather than a single-agent console. Native Merlin itself is **CLI over gRPC**, not a GUI. — [MythicAgents/merlin](https://github.com/MythicAgents/merlin); [Ne0nd0g/merlin README](https://github.com/Ne0nd0g/merlin)
- Security Risk Advisors (Oct 2025) used Mythic’s bundled JupyterLab as the operator-managed automation surface for purple-team test cases against Apollo, then optionally a VECTR Mythic agent for case import. That is a real shipped use of Jupyter-in-Mythic, not a docs-only claim. — [SRA: Automating Purple Team Execution with Mythic and Apollo](https://sra.io/blog/automating-purple-team-execution-with-mythic-and-apollo/)

### Inferences
- For a Sliver web UI, Mythic’s reusable ideas are: (1) **structured task records** with operator, status, comments, tags, deep links; (2) **transform task output in the browser** (tables/buttons) instead of dumping strings; (3) **global file/loot/screenshot search**; (4) **event-driven playbooks** with an approval step; (5) **callback locks + spectator role**. Docker-per-agent is Mythic-the-platform, not something a Sliver client should copy.
- AI chat in Mythic 4.0 / Sage is shipped, with explicit approval UX for write tools. That is real product, but it is new and the docs warn that chat-container secrets are a security boundary. Do not treat “AI operator” as table-stakes.
- Mythic’s graph/tree of callbacks exists but the docs (and Cody Thomas) put far more weight on the table + browsers + search than on a CS-style pivot graph. Mythic uniquely wins *investigation and reporting*; CS/Havoc uniquely win *spatial pivoting*.
- Browser scripts are the highest-ROI Mythic idea that does *not* require Mythic’s architecture: render `ps`/`netstat`/`ls` as tables with action buttons. This fork already has dedicated Files/Processes/Network tabs; the gap is unstructured command output (Exec, alias/BOF results).

### Gaps
- No public quantitative data on how many Mythic operators actually write browser scripts vs using agent defaults.
- Tag data model (tag types, colors, search syntax) is referenced in 4.0 task headers but a dedicated tags reference page was not fetched in this pass.
- Jupyter-in-Mythic is documented and used by SRA for purple team; how often red-team operators use it versus the React UI is unknown.
- TrustedSec/MDSec/Outflank public blogs in this pass did not yield operator-console UX rankings independent of implant OPSEC.

## What does Havoc / Cobalt Strike do well (session graph, listeners, aggressor/BOF workflow, screenshots, SOCKS)?

### Takeaway
CS defined the operator grammar: pivot graph that *is* the network, listener-centric payload generation, Aggressor as the extension/automation layer, BOF as the post-ex unit, global screenshot/keystroke monitors, and SOCKS as a Beacon job. Havoc is the open-source visual clone (graph + table + loot + scripts + chat) with Python extensions instead of Sleep. Clones that skip the graph, global loot, or script hooks feel like admin panels, not consoles.

### Cited Findings
- **Session graph (CS)**: Pivot Graph is documented as the way to understand Beacon chains (named pipes / TCP). Firewall icon = egress. Color of edges encodes protocol and health. Multi-select, right-click post-ex, hide unlinked sessions. Layout presets (circle/stack/hierarchy) are keyboard-bound. — [CS Session and Target Visualizations](https://hstechdocs.helpsystems.com/manuals/cobaltstrike/review/userguide/content/topics/ui_session-target-visualizations.htm)
- **Session graph (Havoc)**: View → Session View → Table or Graph. Official screenshots include `FullSessionGraph.jpeg`, `SessionGraph.png`, `SessionGraphSmbEkko.png`, `LateralMovement.jpeg`. Privileged sessions are red with lightning; table uses red ID font. Graph is the default “wow” screenshot on the README. — [Havoc README](https://github.com/HavocFramework/Havoc/blob/main/README.md); [Havoc screenshots](https://github.com/HavocFramework/Havoc/tree/main/assets/Screenshots); [r1ckyr3c0n Havoc UI](https://medium.com/@r1ckyr3c0n/havoc-c2-framework-part-2-client-user-interface-2024-c029322527f1)
- **Listeners (Havoc)**: View → Listeners tab in the bottom pane; Add opens Create Listener. Types: HTTP, HTTPS, SMB, External C2. Host rotation, bind 0.0.0.0 / 127.0.0.1 / teamserver IP. SMB pipe names can mimic common Chrome pipes (operator writeup). Creating a listener posts to Event Viewer. Teamserver README lists HTTP/HTTPS listeners, customizable C2 profiles, External C2, payload generation (exe/shellcode/dll), multiplayer. — [r1ckyr3c0n Havoc UI](https://medium.com/@r1ckyr3c0n/havoc-c2-framework-part-2-client-user-interface-2024-c029322527f1); [Havoc README](https://github.com/HavocFramework/Havoc/blob/main/README.md)
- **Listeners (CS)**: toolbar button to create/edit listeners; payload generation is listener-centric (stageless exe/DLL, macros, etc. from the same toolbar). Exact 4.13 listener-management HTML 403’d in this pass; 4.6 PDF TOC lists “Listener and Infrastructure Management” as its own chapter after Data Management. — [CS 4.6 user guide PDF TOC](https://hstechdocs.helpsystems.com/manuals/cobaltstrike/current/userguide/content/cobalt-4-6-user-guide.pdf)
- **Aggressor / BOF (CS)**: Aggressor Script is the preferred way to add features, override behaviors (kits), and automate. Loaded via **Cobalt Strike → Script Manager**. Script Console under **View → Script Console**. Headless `agscript` for bots (force DNS check-in, email on new session). Popup hooks (`popup ssh`, beacon menus) extend right-click. `on beacon_initial` / `on beacon_checkin` automate first-checkin playbooks (`initial.cna`). BOF is the in-Beacon post-ex unit; 4.13 adds Beacon Interpreter (C compiled to bytecode VM) and `inline-execute-pe` (BOF-PE) plus a richer process explorer (integrity, command line). Community scripts add Slack notifications, process-tree coloring, bulk checkin/jobs. — [cobaltstrike.com/aggressor-script](https://www.cobaltstrike.com/aggressor-script); [Aggressor examples README](https://github.com/Cobalt-Strike/aggressor_script_examples/blob/main/readme.md); [initial.cna](https://github.com/Cobalt-Strike/aggressor_script_examples/blob/main/examples/initial.cna); [CS 4.13 blog](https://www.cobaltstrike.com/blog/cobalt-strike-413-lost-in-translation); [bluscreenofjeff/AggressorScripts](https://github.com/bluscreenofjeff/AggressorScripts)
- **Scripts / BOF (Havoc)**: Scripts menu + Scripts Manager tab; Load Script for Python extensions (not arbitrary Impacket scripts — they must follow the Havoc agent/Command API). Script Console is a Python interpreter against the client. Built-in examples: havoc-bloodhound, havoc-ligolo, auto_suite (Auto Search / Recon / Persist / RDP). Demon `help` lists Type, Description, and chaining `help <cmd>` shows Behavior (OPSEC hint). `dotnet inline-execute` is the CS execute-assembly analogue. Modules/BOF-style extensions live in [HavocFramework/Modules](https://github.com/HavocFramework/Modules) and [havoc-py](https://github.com/HavocFramework/havoc-py). — [r1ckyr3c0n Havoc UI](https://medium.com/@r1ckyr3c0n/havoc-c2-framework-part-2-client-user-interface-2024-c029322527f1); [Havoc Python Command API](https://mintlify.wiki/HavocFramework/Havoc/api/python/commands)
- **Screenshots / loot (Havoc)**: `screenshot` prints success in the Interact tab but the image lives under **View → Loot** (table of AgentID + Screenshots/Downloads, preview on the right). Same for downloads. This is the CS “global View → Screenshots” pattern. — [r1ckyr3c0n Havoc UI](https://medium.com/@r1ckyr3c0n/havoc-c2-framework-part-2-client-user-interface-2024-c029322527f1)
- **Screenshots (CS)**: inject into a chosen PID (or temp process); results go to a global dialog, not the console. Ctrl+P/T/Shift+T screenshot the *operator UI* itself for reporting. — [CS Keystrokes and Screenshots](https://hstechdocs.helpsystems.com/manuals/cobaltstrike/current/userguide/content/topics/post-exploitation_keystrokes-screenshots.htm); [CS Everything Logs](https://hstechdocs.helpsystems.com/manuals/cobaltstrike/current/userguide/content/topics/blog_let-the-logs-out.htm)
- **SOCKS (CS)**: documented above; proxychains / MSF `setg Proxies` is the intended operator workflow. HTTP Beacon is recommended for pivoting latency; DNS TXT if you must pivot over DNS. — [CS SOCKS Proxy](https://www.cobaltstrike.com/help-socks-proxy-pivoting)
- **File / process explorers (Havoc)**: right-click session → Processes or File Explorer opens bottom tabs (not a separate SPA route). This is the CS Explore menu. — [r1ckyr3c0n Havoc UI](https://medium.com/@r1ckyr3c0n/havoc-c2-framework-part-2-client-user-interface-2024-c029322527f1)
- **Team chat**: both CS event log and Havoc Teamserver Chat are always-on multiplayer. Havoc screenshot set includes `MultiUser.png` and `MultiUserAgentControl.png`. — [Havoc screenshots](https://github.com/HavocFramework/Havoc/tree/main/assets/Screenshots)

## Are there existing Sliver GUIs besides this fork, and what do they have that this fork lacks?

### Takeaway
Yes — a crowded field in 2025–2026. The BishopFox/Armory **official Electron GUI** is the capability ceiling (topology, command palette, native console fallback, websites, RDP, cloud). **Siren** is the closest “operator workbench” (graph + tags/notes/cases + JS automation + BloodHound). **Mr-In4inci3le** is the closest CS/Havoc clone (pivot graph, Ctrl+K, script recipes). **Argus-Sliver** and **MindPalace** are the other web UIs. **sliver-py** / **sliver-script** are libraries, not GUIs. This fork is the lightest *web* client with the deepest per-session tab set, but it lacks a global spatial graph, palette, tagging, playbooks, reporting, team chat, and a native console fallback.
