# Tradecraft capability gaps a Sliver web UI can close

## What do operators still do in sliver-client CLI because GUIs are incomplete (armory, extensions, reactions, builders, wasm, crack, generate-more, regenerate, profiles)?

### Takeaway
This Go-embed React client already wraps most session/beacon/listener/generate RPCs, including regenerate, implant profiles, aliases-as-tar.gz, HTTP C2 save, traffic-encoder list, and loader wrap EXE. Operators still fall back to `sliver-client` for **client-local** workflows that never became gRPC (armory index/search/install-all, reactions, MCP, alias/extension command registration) and for **server RPCs this UI never exposed** (Wasm WASI execute, traffic-encoder add/rm, Crackstation, Cursed, real external builders, generate `--canary` / `--spoof-metadata` / `--external-builder`). There is **no** Sliver command named `generate-more`; the closest CLI surfaces are `regenerate`, `profiles generate`, and `generate traffic-encoders`.

### Inferences
- Highest CLI-escape value for **this** codebase is not another generate RPC page. It is wrapping **already-existing** RPCs the UI forgot (Wasm exec, TrafficEncoderAdd, real `Builders()`, canary domains on generate, remaining limit_* fields) plus a **backend helper** that speaks Armory HTTP the same way the official client does, then feeds aliases/extensions into the tar.gz + `RegisterExtension`/`CallExtension` path already present.
- Reactions and armory catalogs are **per-operator-client**. A web UI that installs armory packages only into the sliver-ui process’s `aliases/` dir will not share them with a teammate’s `sliver-client` unless both talk to a helper that writes a shared disk or the team standardizes on this UI as the only client.
- `generate-more` as an operator request is best read as **batch unique-hash builds from a saved profile** (plus SHA256 display), not a missing Cobra verb. `regenerate` already rebuilds from a stored config ID; unique nonce/hash is currently a Loaders-only behavior.
- Crack and Cursed are real operator tools but poor fit for a small embed UI: Crack is a cluster product; Cursed is an interactive Chrome-debug REPL with no RPC. Defer both.
- Crystal Palace and async BOF should wait on upstream; a UI checkbox cannot create those implant capabilities.

### Gaps
- Default armory index URL, package count, and Minisign key rotation were not re-fetched from a live armory JSON in this pass (client code confirms HTTP+Minisign; exact production URL not cited here).
- No public 2025–2026 operator survey quantifying “I still open sliver-client for X.” Ranking below is inferred from CLI/RPC coverage plus Mythic/Havoc/CS peer UX, not from a counted poll.
- Whether `TrafficEncoderAdd` in v1.7.3 (this module pin) matches current master proto exactly was not binary-diffed against the vendored protobuf; master proto is the cited contract.
- BishopFox/sliver-gui original GitHub repo returns 404; i18n/feature claims come from an archive mirror.

## What workflow glue is missing: host graph, tagging, comments, campaign notes, loot → report, screenshot gallery, file browser as first-class, command palette, session compare?

### Takeaway
Sliver’s server already stores hosts, IOCs, loot files, credentials, screenshots-as-RPC, and a pivot graph. This UI exposes those as **disconnected pages** (loot list, in-memory screenshot thumbs, SessionPicker-wrapped files, nested-`<ul>` pivot tree) with **no** tags, comments, campaign notes, command palette, session-diff, or loot-to-report path. Mythic 4.0 and Ghostwriter `mythic_sync` show the glue operators actually pay for: attributed comments/tags on tasks and files, global search, MITRE on commands, and automatic oplog → report. That glue is mostly **UI + a small local helper**, because Sliver has no comment/tag RPCs.

## What OPSEC dashboards are honest and useful (listener camouflage, canaries, HTTP C2 profile completeness, unique artifact hashes, C2 URL vs live jobs) without claiming AV bypass?

### Takeaway
Honest OPSEC in this product is **traffic and artifact hygiene dashboards**: “you still look like default Sliver,” “this implant’s C2 URL has no live job,” “this binary’s SHA256 collided / is unique,” “this canary fired.” Prior AV/encrypt-at-rest research already forbids FUD and in-tree Donut/ScareCrow. The HTTP C2 page currently ships two templates (`ms-update`, `jquery-cdn`) as a JSON editor with **no** completeness checker against documented default extensions (`.woff` stager, `.html` key exchange, `.js` poll, `.php` session, `.png` close). Canaries are list-only; generate cannot register canary domains. Unique hash is computed client-side for loader wrap blobs only.

Everything in the path except the extension is ignored by the server. Operators configure `stager_file_ext`, `poll_file_ext`, `start_session_file_ext`, `session_file_ext`, `close_file_ext`, headers, cookies, UA, nonce query. — [Sliver Docs: HTTPS C2](https://sliver.sh/docs/?name=HTTPS+C2)
- HTTP staging reuses the regular HTTP listener; default stage-2 URL must end in `stager_file_ext` (default `.woff`). Custom stagers that GET `/whatever.woff` are the documented pattern. — [Sliver Docs: Stagers](https://sliver.sh/docs/?name=Stagers)
